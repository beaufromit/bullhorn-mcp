# CR36: Housekeeping — verified loose ends from the 2026-07 handover audit

## Status: DRAFT (awaiting approval)

Note on numbering: CR35 is left reserved for tool consolidation, which IMPLEMENTATION-PLAN.md and the skill library already reference by that number. This CR was authored 2026-07-04 as part of the handover; every item below was verified present in the codebase at v0.0.46.

## Motivation

Seven small, independently verified defects and drift items accumulated across recent sprints. None justifies its own CR; together they block clean onboarding (fresh installs fail), leave a known injection-pattern class half-fixed, and make the docs of record lie to the AI loop that relies on them. Fixing them in one batch clears the deck before the productization campaign (see NEXT_STEPS.md Priority 0).

## Goals

1. A fresh `uv venv && uv pip install -e ".[dev]"` produces a working server import with no manual steps.
2. Every string interpolated into a Bullhorn /query WHERE clause is guarded, matching the CR33 M2 precedent.
3. The docs of record match reality at v0.0.46.
4. The duplicated note-field constants cannot drift apart again.
5. The skill library and roadmap are versioned in the repo.

## Non-goals

- No tool surface changes (that is CR35 / the productization campaign).
- No behavior change for any currently valid input: the quote guards reject only inputs that would today produce malformed queries or injection.
- The CASE_STUDY.md git-history question is a decision item for the owner, not a change in this CR: either record "accepted: history retained" in IMPLEMENTATION-PLAN.md, or schedule a separate, coordinated history rewrite. This CR only requires that the decision be recorded.

## Changes

### pyproject.toml
- Add `fastmcp` to `[project] dependencies` with a bound reflecting the installed version (3.2.4 as of 2026-07-04), e.g. `fastmcp>=3.2,<4`. Rationale for the upper bound: the Sprint 15 post-tag breakage came from an unpinned FastMCP major-version jump.

### src/bullhorn_mcp/server.py — get_job_submissions
- Guard the `status` parameter before interpolation into the WHERE clause: reject values containing a single quote with the same structured error and wording pattern used by `list_placements` (CR33 M2 fix).

### src/bullhorn_mcp/client.py — resolve_owner
- Guard the owner name before interpolation into the CorporateUser WHERE clause: reject or escape single quotes; on rejection raise ValueError with a message naming the offending value.

### src/bullhorn_mcp/identity.py — resolve_caller
- Guard the email claim before interpolation into the CorporateUser WHERE clause: a single quote in the email raises IdentityResolutionError (an email containing a quote cannot match a legitimate CorporateUser here and is more likely a malformed or hostile token claim).

### src/bullhorn_mcp/server.py — note constants
- Replace `_NOTE_SEARCH_DEFAULT_FIELDS` with a reference to `_NOTE_DEFAULT_FIELDS` (they are byte-identical; they diverged once, CR22). Remove the unused `_NOTE_ENTITY_SUBJECT_FIELD` dict (the live equivalent lives in client.py `add_note`; confirm no references first: `grep -rn "_NOTE_ENTITY_SUBJECT_FIELD" src/ tests/`).
