Subject: /search/Note returns 0 results for notes that exist (corp 5v598g, rest21)

We are integrating against the REST API for corporation ID 5v598g on rest21.bullhornstaffing.com, and we cannot get any results out of `/search/Note`. Your published REST documentation lists Note among the entities supported by the `/search` endpoint and does not mention any per-tenant configuration needed to use it, so I assume we have something wrong on our side and would appreciate a sanity check.

The clearest case is a single note looked up by its primary key. All of the following are read-only GETs made with the same BhRestToken in one session. `GET /entity/Note/2650512?fields=id,action,dateAdded,isDeleted` returns the note with `"isDeleted":false`, and `GET /entity/Candidate/172155/notes?fields=id,action` also returns it. But `GET /search/Note?query=id:2650512&fields=id,action&count=5` returns `{"total":0,"start":0,"count":0,"data":[]}`. Broadening it does not help: `GET /search/Note?query=id:[0 TO 99999999]&fields=id&count=5` also returns `total: 0`. As a control, the identical query shape on another entity works fine on the same token: `GET /search/JobOrder?query=id:[0 TO 99999999]&fields=id&count=1` returns `total: 50271` with data.

What puzzles us most is that the note data does appear to be indexed and reachable, just not through `/search/Note`. Querying the note fields as nested fields on the parent entity works correctly: `GET /search/Candidate?query=notes.action:"Agent added"` returns `total: 71`, and `GET /search/Candidate?query=notes.comments:"Application Triage"` returns `total: 71`, both with sensible data, while control queries for values that should not match correctly return `total: 0`. So the same underlying note content that `/search/Note` cannot find is being matched successfully via `notes.action` and `notes.comments` on the Candidate index.

That leaves us with three questions on `/search/Note` itself. Are we constructing the request incorrectly, and if so what should it look like? Does Note search depend on something on our account that is not covered in the public docs? If neither applies, could you check whether Note search is functioning correctly for this corporation? And one question on the approach: we cannot find the `notes.action` nested-field syntax documented anywhere, so before we build on it, is it a supported and stable way to filter by note fields, or is it something we should not rely on? Related to that, `GET /query/Note?where=id=2650512` returns HTTP 400 with `"Query operation not supported for Note, please use /search call instead."`, so if there is a different recommended way to retrieve the note records themselves filtered by `action` across the whole account, we would rather adopt that than keep guessing.
